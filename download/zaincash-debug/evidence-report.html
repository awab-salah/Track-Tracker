4. Bugs Fixed in Our Integration

  1. Resolved git merge conflict in zaincash.ts (lines 601, 696, 700 had <<<<<<< HEAD markers preventing TypeScript compilation)
  2. Use CORRECT customer wallet MSISDN 9647802999569 in /transaction/processing and /transaction/processingOTP (was incorrectly using merchant MSISDN 9647835077893 as the payer — root cause of the original "Wrong Credentials" errors)
  3. Use SECURITY DEFINER RPCs (get_payment_record, update_payment_record) to bypass RLS on payment_records table (no UPDATE policy existed; direct PostgREST PATCH silently returned 204 with 0 rows)
  4. Fix company filter from companies?id=eq.${companyId} to companies?name=eq.${encodeURIComponent(companyId)} — companyId is the company NAME (text), not the UUID (per schema.sql comment: "company_id stores the company NAME, not the UUID id")
  5. Change serviceType from invalid 'subscription' to valid 'Other' (per Laravel README: allowed values are Book, Food, Grocery, Pharmacy, Transportation, Other)
  6. Added _debug field in POST callback response for diagnosing RLS/configuration issues
  7. Added /api/zaincash/debug-complete-payment endpoint for server-side payment testing (Cloudflare blocks local requests to test.zaincash.iq, but Vercel can reach it)
